Overview — how this studio works

UI Forge is not another autonomous coding harness. It is a studio for testing UI skills: pick a combination, run the same task with it, compare the rendered result side by side, and rank combinations by fewest defects. Skill sources stay read-only, skill instructions are preserved, and only skills actually read in full count as used.

Insights — what the experiments actually showed

Provisional ranking, repeats averaged where available. Ranked on defects left known (0 for 55 of 56), thoroughness of checking, accessibility work, working interaction, conflict-resolution quality, and repeat consistency — not on rendered visual feel, which was measured only for scroll, console errors, and text presence.

Defects found + fixed per variant

“Found + fixed” measures checking thoroughness as much as combo quality — a builder that checked harder finds more. Gold bars are the top five.

Repeat consistency — did the win reproduce? (now 3 runs)

  • pstack+ecc+custom (04 / 13 / 53): 7, 1, 5 — average 4.33. All three runs are the top 3, and the same 2 conflicts were resolved identically in all three (press 0.96, stagger 100ms). 04 still wins after 3 runs.
  • PanelUI web (07 / 14 / 54): 4, 5, 1 — average 3.33. All three runs in the top 6; same defect classes in runs 1–2, a new class (KPI footer clipping) in run 3.
  • Typography → Layout (02 / 12): 0, 4 — average 2.00. Quality held; count did not reproduce.
  • Full UI stack (30 / 55): 1, 1 — average 1.00. Defects reproduced exactly; conflict count did not (10 → 19, more granular logging in run 2).
  • Lesson: no defect count is a reproducible score — the same combo produced 7, 1 and 5 across three fresh builders. This ranking uses repeat averages for repeated combos.

Order effect + ECC alone vs pstack alone

  • Order — five points, still inconclusive: 02 (Typography → Layout) 0; 11 (Layout → Typography) 5 incl 1 HIGH; 10 (Colors → Typography) 4; 50 (Layout → Colors → Typography) 1, 9/9 headless PASS; 45 (six skills in order) 2. No direction is consistent — builder variance still dominates.
  • 51 ECC alone: 4 fixed, #15. ECC carries real design guidance on its own (composition, immutable state, design direction).
  • 52 pstack alone: 1 fixed, #49. Process only — every visual choice was an unguided neutral default, named as such by the builder.
  • 03 pstack + ECC: 0 defects, #9. The combination's value is now measurable: ECC supplies the design, pstack supplies the checking rigour. Neither alone beats the combination.

Conflict findings — two design systems, one page (now 64 total)

  • 26 Astryx + OpenSourceUI — 12 conflicts. Radius: Astryx 12/10/6 beat OSUI 16px. Elevation: OSUI flat won — the frosted-glass notification banner was flattened, the most visible casualty.
  • 27 PanelUI + Astryx — 9 conflicts. One merged token layer (--ax-* values, --pui-* roles). Radii: shadcn scale won. Charts: PanelUI BarChart won (Astryx charts are @canary-only).
  • 30 full UI stack — 10 conflicts. Press 0.96, stagger 100ms, easing split by use; Astryx values on PanelUI semantic names. Still shipped with 0 defects left.
  • 41 PanelUI + OpenSourceUI — 14 conflicts. OSUI flat cards beat PanelUI Frame bands; PanelUI's 5 status roles win, but its indigo --info hue was remapped to OSUI cyan. The merge itself broke nothing (0 defects).
  • 55 full UI stack, run 2 — 19 conflicts. better-ui beat Emil on press, easing, stagger and entrance; PanelUI beat Astryx as the component system. Run 2 logged more granular conflicts than run 1's 10 — the merge did not get worse, the logging got better.
  • Lesson: merges work, but every one costs a named decision and at least one visible casualty. No variant failed to build; no conflict was unresolvable.

What worked

  • Process beats any single skill — and it reproduces: pstack + ECC + custom (04/13/53) is #1/#2/#3 after three independent runs. The rigour (prove-it-works, checklists) caught what design systems alone did not.
  • One strong component system is enough: PanelUI web alone (07/14/54) is #4/#5/#6 after three runs — NavRail, KPI, BarChart, Table, Frame as a complete kit.
  • ECC alone builds; pstack alone checks: 51 (ECC alone) fixed 4 and ranks #15; 52 (pstack alone) fixed 1 and ranks #49, with every visual choice an unguided default. The combination (03) is #9 with 0 defects.
  • Single atomic skills are measurable: layout alone (08) and colors alone (09) each fixed real, specific defects — 2 and 3 — proving the singles do visible work. Accessibility-first (43) fixed 5, the most of any new single/pair.
  • “Everything” is viable, not magical: the full stack (30/55) ranks #7/#8 — good, but not better than the focused 04 combo, and it cost 10–19 recorded decisions.

Honest limits

Layout, horizontal scroll, console errors and rendered text are measured (headless Chromium 156, all 56 variants, 1280px and 390px). Visual feel, taste, touch behaviour, screen readers, and Safari/Firefox are not — no variant was eyeballed on real hardware. One run per variant except the three repeats, and defect counts did not reproduce across repeats. Astryx, OpenSourceUI and PanelUI were adapted to single-file HTML, not real React / Expo builds. This ranking is provisional until repeated — see experiments/RESULTS.md for the full method.
